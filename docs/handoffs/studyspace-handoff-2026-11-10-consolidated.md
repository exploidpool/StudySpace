## Цель продукта

StudySpace — бесплатное Telegram Mini App для организации учёбы: расписание, задания, предметы, конспекты, файлы и обмен материалами. Долгосрочная аудитория — студенты колледжей и техникумов. Ближайший полезный релиз сужен до пилота для группы ИС-942.

Приложение должно оставаться реальным рабочим продуктом, а не демонстрационным макетом. Сохраняется существующая навигация:

1. Главная.
2. Расписание.
3. Задания.
4. Материалы.
5. Профиль.

## Выбранное файловое хранилище для этапа 4

Исходное ТЗ предлагало Cloudflare R2, но позднее пользователь выбрал приватный Telegram-канал через Bot API, чтобы не требовалась привязка карты. Это решение отражено в текущем README и старом handoff.

- В D1 будут храниться метаданные, Telegram `file_id`/идентификатор сообщения и права доступа.
- Фактические файлы будут находиться в приватном Telegram-канале платформы.
- Учитывать лимит скачивания Bot API около 20 МБ на файл, проверив актуальную официальную документацию перед этапом 4.
- Это решение не относится к OCR-фото расписания: фото расписания в пилоте не сохраняется и не загружается на backend.

## Текущий приоритет: этап 3A — расписание ИС-942

### Пользовательский результат

- На главной вкладке показывается расписание на сегодня.
- Во вкладке «Расписание» показывается вся выбранная неделя.
- Существующие вкладки и `TabBar` не меняются.
- Обычный студент только читает опубликованное расписание.
- Администратор загружает фото, проверяет OCR-результат, исправляет его и только затем публикует.

### Формат исходной фотографии

- Одна фотография содержит расписания нескольких групп на одну конкретную неделю.
- Макет и расположение блоков могут меняться.
- Над каждым расписанием указан код группы.
- Нужно найти только блок `ИС-942` и игнорировать остальные группы.
- Расписание различается по чётным/нечётным неделям и содержит разовые изменения, но отдельные шаблоны чётности не нужны: каждая публикация привязана к конкретному `week_start`.
- Встречается деление `первая подгруппа / вторая подгруппа`.

### Согласованный поток администратора

1. Администратор выбирает понедельник недели; по умолчанию предлагается текущая неделя.
2. Выбирает PNG/JPG с расписаниями нескольких групп.
3. OCR работает в браузере через Tesseract.js, без платного API.
4. Система ищет заголовок ИС-942 по распознанному тексту и координатам.
5. Показывает предполагаемую область; администратор подтверждает или вручную корректирует прямоугольник.
6. Выбранная область распознаётся повторно.
7. Консервативный парсер создаёт черновик; сомнительные строки не угадываются, а показываются отдельно.
8. Администратор исправляет таблицу вручную.
9. Черновик сохраняется на backend.
10. Отдельное явное подтверждение публикует неделю.

Ни один OCR-результат не публикуется автоматически. Полностью безошибочное распознавание произвольных таблиц не обещается; корректность опубликованных данных обеспечивает администраторская проверка.

### OCR и приватность

- Выбран подход Tesseract.js в браузере/WebAssembly.
- Требуются языки `rus+eng`, coordinates/blocks output, auto-rotate и распознавание выбранного rectangle.
- Worker/core и языковые данные планируется поставлять статическими ресурсами проекта, без runtime-зависимости от стороннего CDN.
- Исходное фото не покидает браузер и не сохраняется.
- На backend передаётся только структурированный черновик.
- Для разработки нужны 3–5 репрезентативных фото разных форматов. Оригиналы нельзя добавлять в Git без отдельного согласия; для тестов использовать обезличенные OCR JSON-фикстуры.

### Модель данных пилота

`schedule_weeks`:

- `id`
- `group_code` (в пилоте только `ИС-942`)
- `week_start` (понедельник конкретной недели)
- `status: draft|published|archived`
- `created_by`
- даты создания, изменения и публикации

`lessons`:

- ссылка на `schedule_week_id`
- `day_of_week: 1..7`
- `start_time`
- `end_time` (может отсутствовать)
- `subject_name`
- `classroom` (может отсутствовать)
- `teacher` (может отсутствовать; это текст, не роль пользователя)
- `subgroup: 1|2|null`
- `position`

Для одного дня и времени разрешены две записи, если они относятся к разным подгруппам. Общее занятие имеет `subgroup = null`. Пока подгруппа пользователя не хранится в профиле, UI показывает обе подгруппы с явными метками.

Только одна опубликованная версия активна для `group_code + week_start`. Исправление опубликованной недели создаёт новый черновик; при публикации прежняя версия архивируется атомарно. Восстановление и просмотр архива не входят в пилот.

### Права и API

Все маршруты используют подтверждённый Telegram-контекст.

Планируемые маршруты:

- `GET /api/schedule/today`
- `GET /api/schedule/week`
- `POST /api/schedule/drafts`
- `PUT /api/schedule/drafts/:id`
- `POST /api/schedule/drafts/:id/publish`

Студент читает только опубликованные данные. Write-маршруты требуют серверную роль `admin`; скрытие кнопок во frontend не считается защитой. Первичного администратора пилота владелец проекта назначает вручную в D1. Публичного повышения роли нет.

До этапа 5 все авторизованные пользователи пилота считаются участниками ИС-942. Позднее `group_code` заменяется/дополняется связью со `study_groups` и серверной проверкой членства.

### Время

- Пилот использует `Asia/Novosibirsk` для определения «сегодня».
- Позднее приоритет может перейти к валидному часовому поясу профиля/группы.
- Чётность недели не используется как правило хранения: фактическая публикация всегда привязана к `week_start`.

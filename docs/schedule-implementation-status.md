## Последняя проверка

Исходное фото получено в `samples.local`. На нём локально сравнены общий OCR, отдельный столбец времени и повторное чтение отдельных чисел. Лучший из проверенных вариантов: увеличение выбранной таблицы, удаление длинных горизонтальных/вертикальных линий, PSM.SPARSE_TEXT. Цифровые и построчные проходы хуже и в рабочий импорт не добавлены. После обработки распознаны все 6 дат, в редактор попали 6 строк; остальные читаемые, но сомнительные строки вынесены в отдельный список ручной проверки. Это частичный результат, полное расписание автоматически не восстановлено.

Исправлен сдвиг пар времени при нечитаемом токене: теперь токен сохраняет своё место, слишком далёкие начало/окончание не объединяются. Спорные строки не содержат угаданного времени; их можно явно перенести в редактор или пропустить. Сохранение заблокировано до разбора списка. В редакторе обязательны начало и предмет. Добавлены регрессионные проверки обработки сетки и повреждённых часов: frontend — 15/15 PASS. Полный сценарий после этой правки внутри Telegram ещё требует приёмки; исходник и диагностические результаты исключены из Git.

Пользователь предоставил реальный OCR-текст: даты и часть предметов читаются, но столбец времени превращается в `SZ`, `EB`, `EE` и другие символы. Причина пустого черновика теперь связана прежде всего с качеством OCR времени, а не только с форматом дат. Нельзя восстанавливать часы из этих символов без источника. Подготовлен `frontend/scripts/check-schedule-ocr.mjs` для локального сравнения общего OCR и отдельного цифрового прохода по столбцу времени. Исходники и результаты — в исключённой из Git папке `samples.local/`; внешние сервисы не используются. Проверены справка скрипта и исключение папки из Git. Для запуска на реальном изображении ожидается исходный файл в этой папке.

Реальное фото удалось вставить через буфер в Telegram; OCR завершился, но первоначальный парсер отклонил результат из-за отсутствия ровно шести дат. Добавлены объединение фрагментов даты на одной строке, частичное заполнение только однозначных дней (без сдвига после пропуска даты), блок исходного распознанного текста и корректное сообщение при нуле занятий. Перед OCR выбранная область физически обрезается и увеличивается до 3 раз в пределах лимита памяти; поворот больше не меняет координаты прямоугольника на полном фото. Frontend: 12/12 тестов и сборка прошли. Повторное распознавание реального фото после этой правки ещё не подтверждено.

При ручной проверке в Telegram Desktop системное поле выбора файла не открывает диалог. Добавлен `PhotoInput.tsx`: явная русская кнопка с синхронным `showPicker`/`click`, вставка PNG/JPG из буфера (кнопка и поле Ctrl+V), перетаскивание файла, сообщения об ошибках. Новые элементы проверены визуально в Telegram. Системный диалог в текущем WebView по-прежнему не открылся; вставку реального изображения и последующий OCR ещё должен подтвердить пользователь. Frontend собирается, 8 существующих тестов проходят.

Пользователь установил зависимости frontend и backend. Lock-файл frontend обновлён, локальные OCR-ресурсы подготовлены. Сборка frontend, TypeScript backend и все 13 тестов прошли. Обе миграции успешно применены к локальной D1 через Wrangler. Реальное распознавание фотографий и Telegram-приёмка остаются непроверенными.

## Ограничения и продолжение

Доступ к npm registry из среды агента заблокирован (`EACCES`), но установка пользователем завершилась успешно. Ресурсы `public/ocr` генерируются из установленных пакетов автоматически перед dev/build, в Git не включаются.

`wrangler dev --local --port 8790` остановился на ошибке esbuild: `Cannot read directory "../../../../..": Access is denied`, затем `Could not resolve .../backend/src/index.ts`. Это блокер локального запуска из ограниченной среды агента. Миграции через Wrangler работают. Дочерний процесс dev завершился; постоянного сервера агент не оставил.

Команды проверки в PowerShell (зависимости уже установлены):

```powershell
Set-Location C:\Users\Administrator\Documents\Codex\my-proj\StudySpace\frontend
npm.cmd test
npm.cmd run build
Set-Location ..\backend
npm.cmd test
npm.cmd run typecheck
```

Для продолжения: запустить backend и frontend в отдельных терминалах (`npm.cmd run dev` в каждой папке) и пройти сценарий импорт → ручная сверка → сохранение → отдельная публикация. Миграции уже применены **локально**; удалённая D1 не менялась. Для реального Telegram-входа нужен локальный `backend/.dev.vars` с токеном и отдельно согласованный доступный HTTPS-адрес; публичный туннель автоматически не создаётся.

Добавлен `backend/test/schedule-api.test.mjs`: исполняет настоящие Hono-маршруты и Telegram middleware под Node.js с синтетической корректной HMAC-подписью и SQLite-адаптером D1 в памяти. Проверены `401`, `403`, валидация понедельника, невидимость черновика студенту, публикация, запрет редактирования опубликованного, замена и повторная публикация старого черновика. Это не проверка среды Workers; приёмка с реальным Telegram-клиентом остаётся обязательной. Автоматический OCR предоставленных трёх изображений ещё не проверен. Порог уверенности и пределы размера изображения предварительные.

Парсер поддерживает распознанные слова с координатами, даты внизу дневных блоков и разделение подгрупп `/`. Это эвристика для предоставленного формата, не универсальное распознавание таблиц. Если границы дней не распознаны, данные вводятся вручную. Колонка замен и рукописные исправления требуют сверки, геометрию области после поворота фото необходимо проверить на реальном OCR.

Черновик хранится сервером, но список и повторное открытие сохранённых черновиков после перезагрузки страницы пока не реализованы. Исправление публикации возможно через создание нового черновика; автоматическое копирование опубликованной недели в редактор пока отсутствует.

Тесты требуют Node.js 26 (встроенная обработка TypeScript, `node:sqlite`, `registerHooks`). Это требование тестового режима, а не новая проверенная минимальная версия приложения. API-тест также требует установленный Hono.

`npm.cmd test` во frontend: 8/8 прошли (5 тестов парсера и 3 дат). `npm.cmd test` в backend: 5/5 прошли (API, валидация, часовой пояс, SQLite и публикация). `npm.cmd run build` frontend, `npm.cmd run typecheck` backend и `git diff --check` прошли. Эти результаты не заменяют проверку в Workers и Telegram.

Удалённая база, GitHub и размещённое приложение не изменялись. Коммитов нет.
